### How it fits together
- **Table rules** go in the GM's system prompt from the campaign's settings.
- **Auto dice:** the GM calls a `roll_dice` tool, the app rolls real dice (a cryptographic random
  generator), and the GM narrates from the result. Rolls are saved on the reply and shown above
  it, live while streaming.
- **The character sheet** rides in the per-turn GM notes, at the end of the prompt, so updating
  it every turn never disturbs the prompt cache. The router updates it in the background after
  each reply. Every version is snapshotted, so taking a turn back (Esc, retry, rewinds) also
  undoes that turn's sheet changes. You can edit it from the **Sheet** button.
- **The story arc** sits in the GM's system prompt. It only changes between sessions, so caching
  holds.
  - Filing updates its Progress section, and revises the rest if play has gone somewhere else.
  - Old versions are kept in `arc-history/`.
  - A short or truncated revision can't wipe it.
  - The play page is blocked from fetching it.

## Decisions I made (easy to change)
- **Existing campaigns default to no dice**, so Calvin's story doesn't suddenly start rolling.
  New campaigns default to auto dice and normal stakes. You can change either per campaign in
  admin → Edit.
- **Existing campaigns have no story arc** until you ask. Admin → *Story arc (spoilers)* →
  *Write a story arc* builds one from the current brief. Calvin's campaign doesn't have one.
- **No starting sheet for existing or imported campaigns.** It's created on the first turn after
  the upgrade, from the brief and that exchange.
- **The arc prompt forbids inventing the player character's past or relatives.** The first test
  arc gave the PC a secret family history.

setup, before playing a turn. I didn't restart it. At that point the host had about 0.6 GB of
RAM free, with 15 GB of swap in use. The biggest users were llama.cpp processes' host RAM, not
this app:

| Process | Resident RAM |
|---|---|
| `qwen3.8-27b` (:8038) | 8.2 GB |
| `qwen3.5-9b` (:8035) | 4.7 GB |
| `qwen3.6-27b` (:8036), still running | small in RAM, but holds GPU 0 |

Worth checking the flags on the two new instances (`--no-mmap`, or anything that keeps a copy
in RAM), and whether :8036 is still needed.

To run the soak once memory allows (about 90 minutes, uses a test vault):
